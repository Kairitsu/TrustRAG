## Issue #20: Rerank 配置保存失败 (PUT 500)

### 根因分析
`update_config()` 使用动态 SQL 构建 UPDATE 语句，将所有字段值通过 `to_string()` 统一转为字符串后存入 `Vec<String>`，然后逐个绑定。

问题在于：
1. `fallback_enabled` (bool) → `"true"/"false"` 字符串，但 SQLite 列是 `INTEGER NOT NULL`
2. `is_default` (bool) → 同理
3. `top_n`, `initial_recall_k`, `timeout_secs` (i32) → 字符串绑定虽然能被 SQLite 隐式转换，但不规范
4. `updated_at` 更新使用 `#[cfg(sqlite_mode)]`，条件编译标志可能未正确设置

### 修复方案
- [ ] **20.1** 重构 `update_config` — 不再使用统一的 `Vec<String>` 绑定，改为分类处理：字符串字段、整数字段、布尔字段各自用正确的类型绑定
- [ ] **20.2** 修复 `updated_at` 更新逻辑 — 确保 SQLite 模式下 `updated_at` 正确更新
- [ ] **20.3** 前端错误提示增强 — Rerank 保存失败时展示后端返回的具体错误信息
- [ ] **20.4** 测试验证 — 编写 rerank_configs 的单元测试
- [ ] **20.5** 提交并回复 Issue

## Issue #25: 知识图谱 ready/completed 状态不一致

### 根因分析
`generate_for_all_documents()` 使用 `processing_status = 'completed'` 筛选文档，但文档处理完成后实际状态为 `ready`。

此外还有：
1. 单文档生成缺少进度反馈
2. `graph_layer` 缺失导致关系图在图层过滤时消失

### 修复方案
- [ ] **25.1** 修复文档状态筛选 — `'completed'` 改为 `IN ('ready', 'completed')`
- [ ] **25.2** 确保生成的实体和关系都有 `graph_layer` 值 — 检查 `knowledge_extraction` 模块
- [ ] **25.3** 前端知识图谱生成进度增强 — 单文档生成增加 loading 状态
- [ ] **25.4** 测试验证
- [ ] **25.5** 提交并回复 Issue
